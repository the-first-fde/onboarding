# 검토·승인(HITL) 업무 정의 — PROVISIONAL

[작성 양식](template.md)을 따른다. 개발용 `.claude/agents/`와 별개다.

- 소유자: 검토·승인 담당 (업무 분할 「4. 사람의 검토 및 승인 (HITL)」)
- 상태: PROVISIONAL — 팀 합의 항목은 [잠정 계약](../docs/contracts/review-approval.md)의 NEEDS_CLARIFICATION을 따른다.
- 목적: 다른 서브에이전트가 만든 초안을 사람(인사 담당자)이 검토하도록 대기열에 올리고, 승인 상태를 관리하며, 승인 전 외부 등록·수정을 막는다.
- 입력: `Draft` (입사자 참조 키, 산출물 종류, 체크리스트 ID, 원본 양식 위치·원문, 초안 내용, 리더 제공 내용 포함 여부), 사람의 `ReviewDecision`.
- 출력: `ReviewItem`(상태·차이 요약·의견·승인 해시·실행 시각), 담당자용 검토 요청, 게이트 결과(통과 / `NotApproved` / `ManualActionRequired`).
- 구현: [review_approval.py](../src/hr_onboarding/workflows/review_approval.py). 현재는 규칙 기반 Python으로만 동작하고 Claude Agent SDK 호출은 없다.

## 확인된 근거

경로·절 번호로만 인용한다. 원문은 옮기지 않는다.

- `02_온보딩/06_입사_안내메일.md` 머리말: 메일은 인사 담당자가 초안 작성·직접 확인 뒤 발송, 자동 발송 없음.
- `02_온보딩/08_첫주_캘린더_요청문구.md` 3절: 계정·장비·팀 권한 요청은 인사 담당자가 작성하고, 받는 쪽이 처리한다.
- `00_공통/02_조직도.md` 3절: 수습 평가와 정규 전환 결정은 소속 본부장이 한다.
- `00_공통/05_AI_사용_보안_가이드.md`: 처우·주민번호·연락처·주소·인증정보는 AI 입력에 넣지 않는다.

## 동작 규칙

1. 초안을 받으면 「초안생성」으로 만들고, 원본 양식과 줄 단위 차이를 센 뒤 「검토대기」로 올린다.
2. 리더 제공 내용이 들어 있으면 「리더 제공 내용 포함, 출처 확인 필요」를 붙인다. 계정 요청이면 「신청 권한이 직무에 맞고 넘치지 않는지」 확인을 제안한다.
3. 인사 담당자만 승인·수정 요청·보류·보류 해제를 결정한다.
4. 승인 뒤 내용이 바뀌면 다시 「검토대기」로 돌리고 재승인을 받는다.
5. 외부 등록·수정 전에는 `require_approved`를 반드시 거친다. 승인완료이고 승인 당시와 내용이 같을 때만 통과한다.
6. 메일 발송·입사 확정·합격/불합격 결정·정규 전환 결정은 승인돼도 자동 실행하지 않고 담당자에게 넘긴다.
7. 실행(수동 포함)이 끝나 `executed_at`이 기록되면 검토 대기열에서 뺀다.

## 잠정 가정

계약 문서 A1~A5를 따른다. 확정 정책으로 쓰지 않는다.

## 권한과 안전

- 허용 도구: 없음
- MCP: 미연결, 쓰기 금지. 다른 담당자의 MCP mock 쓰기 앞에서 게이트만 제공한다.
- 승인: 외부 실행은 명시 승인 필요. 실제 메일 발송과 입사 확정은 사람이 수동으로 한다.
- 저장: 검토 항목과 기록에 본문·이름·연락처를 남기지 않고 해시와 차이 요약만 남긴다.

## 오류·재시도·멱등성·보존 기간

- 전이표에 없는 전이는 `InvalidTransition`, 권한 없는 결정은 `UnauthorizedReviewer`로 거부한다.
- 자동 재시도·자동 승인은 없다. 사람 결정은 LangGraph `interrupt`로 기다린다.
- 같은 항목·같은 내용을 다시 올리면 기존 항목을 돌려준다.
- 영속화(checkpointer)와 보존 기간은 팀 합의 전이라 정하지 않는다. 지금은 메모리 대기열만 있다.
