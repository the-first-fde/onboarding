# Claude Code로 계획하고 사람이 검토하기

**학습 목표**는 AI가 읽는 자료, 허용된 도구, 실제 변경을 사람이 구분하고 승인하는 것이다. 설치와 bootstrap을 마치고 [팀 보안 기준](security-guide.md)을 읽는다. Claude Code는 대화와 관련 파일을 컨텍스트(context, 현재 판단에 사용하는 자료)로 읽고 도구 요청을 만든다. 파일 내용 전체나 이전 세션을 항상 기억한다고 가정하지 않는다.

## 첫 세션과 권한

```bash
claude --version
git status --short --branch
git diff
```

루트에서 설치 버전, 현재 변경, 추적 파일의 차이를 확인한다. 처음 사용한다면 [공식 설치](https://code.claude.com/docs/en/setup)를 따른다. CLI 버전 조회는 모델 호출을 하지 않는다. 실제 세션에서 루트의 `claude` 실행은 팀의 인증·비용 정책에 따라 사람이 시작할 때만 진행한다. 이 가이드의 인증 세션 실습은 미실행이다.

실제 세션에서 `/permissions`와 `/hooks`로 설정을 확인한다. 권한 질문은 도구에 특정 동작을 허용하는 요청이다. 무엇을 어디에서 실행하는지, 외부 전송·파일 쓰기·비밀 접근이 있는지 읽고 결정한다. 툴이나 편집이 차단되면 정책과 대상 경로를 확인한다. 전체 허용이나 우회 모드로 해결하지 않는다.

## Claude Code 연습 · 기술 테스트를 이해하고 리뷰하기

이 실습은 요청과 사람 확인 절차를 보여준다.

1. “루트와 작업 디렉터리 README·CLAUDE.md, 관련 Spec·잠정 계약과 현재 Git 상태를 읽어줘. `test_graph_runs_without_network`가 보장하는 것과 남은 업무 검증을 설명해줘.”
2. “/plan-task로 바뀔 파일·테스트·외부 동작 여부를 먼저 알려줘.” 사람은 Spec 범위와 계획을 검토하고 적절한 항목만 승인한다. 기술 설명만 필요하면 편집을 요청할 필요가 없다.
3. 승인된 변경만 구현한 뒤 `git status`, diff, 미추적 파일, 실행한 명령과 결과를 비교한다. “이 줄을 지우면 어떤 테스트가 실패하고 왜 그런지 설명해줘.” 검증 명령은 사람이 직접 재실행할 수 있어야 한다.
4. 별도 문맥에서 독립 AI 리뷰를 요청한다. “추가로 영향받는 모듈과 팀 결정이 필요한 불일치를 찾아줘. 필요한 경우 기존 Issue를 확인하고 초안만 제안해줘.” PR 초안은 사람이 증거와 권한을 확인한다.

좋은 프롬프트는 읽을 자료, 작은 목표, 허용 변경, 검증 질문이 있다. 피할 프롬프트는 “전부 고치고 올려”처럼 범위와 승인이 한꺼번에 섞인다. 세션에 내용이 너무 많아지거나 작업이 바뀌면, 승인된 계획·변경 파일·미해결 질문을 짧게 정리해 새 세션이 다시 원문을 읽게 한다. 독립 리뷰에는 구현자의 결론을 그대로 넘기지 않는다. 실제 비밀과 고객사 원본은 컨텍스트에 넣지 않는다.

- [ ] 터미널의 실제 상태와 AI 설명을 대조했다.
- [ ] 도구 요청을 승인하기 전에 대상·부작용을 설명할 수 있다.
- [ ] 동작을 설명하고 테스트의 증명 범위까지 확인했다.
