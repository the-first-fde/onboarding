# 사람과 AI의 공통 리뷰 체크리스트

[리뷰 실습](review-guide.md)에서 방법을 익힌 뒤 PR의 현재 버전에 적용한다. 각 행에 PASS/FAIL/NOT RUN, 근거 파일이나 실행 결과를 남긴다. 적용 대상이 아니라면 사유를 적는다. 이 표는 승인 권한을 대체하지 않는다.

| 확인 항목 | 확인 방법과 증거 | 실패 또는 미실행 처리 |
|---|---|---|
| 범위와 요구 | Spec 인수 조건, 잠정 계약, diff·미추적 파일을 비교 | 범위 밖 변경이나 계약 가정은 요청에서 분리하고 팀 판단이 필요하면 Issue 제안 |
| 코드 이해 | 타입·Docstring·오류·async 경로에서 호출자, 반환과 실패 설명 | 재현 조건과 파일을 첨부하고 결과를 설명할 수 있을 때 재검토 |
| 테스트·커버리지 | verify 결과와 실패 경로, 기술/업무 검증 범위를 구분 | 오류 수정 뒤 재실행, 미실행은 이유를 기록. 커버리지 수치로 업무 적합성을 대신하지 않음 |
| README와 가이드 | 개발 위치·명령·예제·상대 링크를 실제 파일과 대조 | 같은 변경에서 안내 최신화. 문서와 코드의 기준이 불명확하면 사용자에게 보고 |
| 개인정보·비밀 | 파일명 목록, 승인된 diff와 마스킹된 Gitleaks 결과 확인 | 내용 복사 없이 [사고 절차](security-guide.md) 적용 |
| 외부 실행과 승인 | 실제 메일·입사 확정 수동, MCP 쓰기 금지, 개발과 런타임 권한 분리 확인 | 경계 위반 변경은 승인 보류, 승인 주체·조건을 Spec과 대조 |
| CI·Sonar | 최소 권한·고정 SHA·시간 제한·일반 PR secret 없음, Sonar 조건과 실행 상태 | 로컬 PASS와 CI 미실행을 분리. 외부 분석 설정 및 승인은 관리자에게 확인 |
| 리뷰와 복구 | 독립 AI·CI·사람 증거, 승인 이후 diff, 복구 경로 확인 | 현재 버전 재검토·재승인. 병합 문제가 있으면 승인된 revert PR |
| 팀 결정 | No Silent Issues의 보고·중복 확인·초안·승인 기록 | 근거와 영향부터 공유하고 범위 밖 무단 변경 보류 |

가상 판정 예시는 “문서 주소는 정상, 업무 승인 조건은 NOT RUN(샘플·계약 미정), CI NOT RUN(로컬만 수행)”이다. 검토 요청 예시는 “checklist 각 행에 파일이나 테스트 근거를 붙여줘. 판정할 수 없으면 이유를 표시하고 팀 판단 쟁점을 제안해줘”다. 사람은 영향과 재현을 확인하고 [리뷰 양식](../../.github/templates/review.md)에 결론을 기록한다. [기여 기준](../../CONTRIBUTING.md)
