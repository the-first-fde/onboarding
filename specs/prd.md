# PRD · HR Agentic Operations
## 문제와 사용자
HR은 지원자 페이지·메일·체크리스트·챗을 대조하여 입사 의사, 준비 상태, 실제 완료를 확인한다.
리더·버디·총무의 책임과 최신 절차가 다르면 체크 누락과 접근 지연이 발생한다.
HR은 사건의 출처와 시점을 보고 승인하며, 리더·총무·버디는 자기 업무만 확인해야 한다.

## 첫 사용자 흐름
1. ATS/Notion/mock adapter가 지원자와 결과 통보의 근거를 관측한다.
2. 최종 합격과 처우 협의는 채용 케이스에 남긴다. 이 단계에서는 온보딩을 만들지 않는다.
3. Notion 입사확정 블록과 의사 회신을 HR이 대조한다. 누락은 검토 요청으로 남긴다.
4. HR이 정제된 HireConfirmedEvent를 승인한다. 버디·노트북의 null은 정상적인 미확정이다.
5. case+event+outbox+audit를 원자적으로 생성하고 worker가 허용된 준비 요청을 처리한다.
6. 운영 화면에서 상태·근거·재시도·승인 결과를 확인한다.

## 범위
P0: 채용→입사확정→온보딩, ON-01~56 업무 정의, 증거 대사, 승인과 mock 실행, 시간순 replay.
우선 G0 계약 검토와 G1~G2 수직 흐름. 수습 평가 자체, 1on1, 오프보딩은 후속 확장이다.
ON-48~56은 온보딩 일정/연결 지점이며 별도 수습 평가 채점·정규 전환 자동화는 범위 밖이다.

## 성공 조건 (목표, 아직 성과 아님)
업무 생성·기한·조건 정확도 100%, 근거 없는 완료 0, 승인 우회 0, 중복 생성 0,
케이스 간 정보 유출 0. 증거 매핑 95%는 향후 평가 목표다. 업무 시간 절감은 수동 기준선 측정 후 비교한다.

## 확인 필요
첫 주/3주 차의 일반 기한 계산·공휴일/영업일 처리·입사일 변경·입사 취소 보상 정책은 별도 합의한다.
v3.2의 과거 적용 대상과 재기한은 명시 승인된 migration plan으로 확정한다.
초기 mock 승인 토큰은 실제 SSO/RBAC를 대체하지 않는다. 연동별 권한·사용 동의는 아직 확인하지 않았다.

## 게이트
G0: 명세/계약/근거 검토 (초안 작성됨, 최종 승인 미완료).
G1: 합성 handoff 저장과 중복/민감필드 거부 (초기 구현).
G2: outbox mock 실행과 작은 UI (초기 구현, PostgreSQL/브라우저 전체 검증 별도).
G3: 56 업무 엔진과 증거, G4: agent/wiki/승인 실행, G5: 통합 평가·제출 (미구현).
